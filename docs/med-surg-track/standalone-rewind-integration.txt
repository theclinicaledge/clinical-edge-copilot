Standalone Rewind integration — October 18, 2026 Pacific

Implemented
- Extracted the approved player into modules/rewind/RewindPlayer.jsx, with shared
  Steps and CallControl. The Med-Surg track now uses this same player through an
  adapter that retains its original persistence and next-assignment navigation.
- Drowsy Patient and Which Patient First expose optional Rewind in their completed
  standalone debriefs, using the existing three authored variations each.
- Standalone practice uses its own versioned device-local keys. It cannot write
  original Shift or track records. Reviewing feedback does not add an attempt.
- Intro/read/decision/feedback/summary, partial resume and retry remain consistent.
  Standalone summaries return to the library; track summaries retain track navigation.
- Rewind unmounts when its scenario becomes inactive, preventing a retained hidden
  scenario from leaving an open modal over another page.
- Incompatible records block replacement. Storage failures preserve current practice
  in component memory with a visible notice, including within the modal.
- Privacy disclosure includes standalone practice retention and separation.
- Standalone entry remains behind the existing private preview flag. No release,
  deployment, commit, backend changes or new clinical content in this pass.
